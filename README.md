# Agent Workflow Kit

Общие навыки и правила для разработки с AI-агентами. Пользователь описывает рабочую задачу и выбирает подходящий результат, агент ведёт реализацию и проверки.

Версия: **0.1.0**. Источник: https://github.com/UegeneCrabs/agent-workflow-kit.

## Подключить к проекту

Открой в агенте папку рабочего проекта и отправь:

> Подключи библиотеку https://github.com/UegeneCrabs/agent-workflow-kit по READMEconnectAI.md. Для нового проекта используй профиль python-business-web. Если проект уже существует, сохрани его фактический стек и инструкции. Моя задача: …

Подробный порядок — [READMEconnectAI.md](READMEconnectAI.md). Если агент открыл сам репозиторий библиотеки, сначала укажи папку своего приложения: библиотека не является приложением.

## Что входит

- .agents/skills/ —20навыков: конструктор, аналитик, координатор, разработчик, тестировщик и15методов.
- .agents/rules/ —40правил в семи файлах.
- [Профиль python-business-web](.agents/skills/role-skill-builder/assets/stack-profiles/python-business-web.md) — выбранная основа нового бизнес-приложения.
- Шаблоны подключения, внутреннего ТЗ и проектного контекста.

В комплекте только инструкции, metadata и шаблоны. Старый машинный gate, его исполняемые скрипты, испытательные проекты, окружения и история исходного приложения не распространяются. [Заметка о совместимости](.agents/skills/task-coordinator/references/workflow-contract.md).

## Новый и существующий проект

Новый проект: агент уточняет назначение и существенные решения на языке пользователя, применяет выбранный профиль и записывает фактические настройки в .project-agents. До установки компонента проверяет, нужен ли он задаче.

Существующий: читает AGENTS.md, текущие документы, конфигурацию и относящийся код. Использует готовый контекст, сохраняет версии и стек. Подключение библиотеки само по себе не разрешает миграцию проекта.

Общие навыки хранятся рядом с кодом проекта в .agents/. Подключённая версия и источник записываются в .project-agents/library-lock.json. Проектные правила и требования сохраняются в Git вместе с приложением; временная история, секреты, кеши и персональные настройки туда не включаются.

## Работа

Пользователю — описание результата, варианты и последствия. Разработчику — внутреннее ТЗ. Выбор пользователя разрешает выполнение, проверки и исправления в этих границах без подтверждения каждого этапа.

Author gpt-6-astra → reviewer gpt-6.1-sol → coder с наследуемой моделью → три независимых tester gpt-6-astra/gpt-6.1-sol/gpt-6.1-terra. Доступность моделей и инструментов зависит от среды/аккаунта; инструкции не создают отсутствующих возможностей. Неполная панель не называется тремя независимыми passed.

Явный режим «сам, без агентов/испытаний» имеет приоритет. Структурная проверка текста не выдаётся за испытание поведения.

PyCharm не требуется. Если IDE предоставляет python-tools, используется её механизм SDK; иначе определяется реальное окружение проекта по конфигурации и uv. Общие правила не содержат персональных путей.

## Обновления

Проект использует выбранный тег/commit библиотеки. Обновление выполняется отдельным изменением с сохранением локальных дополнений, а не автоматической загрузкой main перед каждой задачей. Ошибки общих правил исправляются в этой библиотеке; продуктовые изменения остаются в репозитории приложения.
