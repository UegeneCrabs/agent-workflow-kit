# Профиль python-business-web

Идентификатор: python-business-web. Версия профиля:1. Предназначен для новых веб-приложений с бизнес-процессами, таблицами, кабинетами и интеграциями. Не универсален для всех типов программ. Применяется при явном выборе этого профиля; существующий стек сам по себе не заменяет.

## Фиксированная основа

- Python3.13; точную patch-версию реально выбранного интерпретатора зафиксировать при создании.
- uv; зависимости и dev-группы в pyproject.toml, точные разрешённые версии в uv.lock; локальная .venv.
- FastAPI и Uvicorn; HTTP API с типизированным JSON.
- Pydantic2 для проверяемых внешних контрактов, pydantic-settings2 для настроек.
- Frontend: HTML/CSS/JavaScript отдельными файлами; взаимодействие с backend через JSON API.
- HTTPX AsyncClient, когда есть исходящие HTTP-запросы.
- Ruff lint/format и mypy strict для нового типизированного Python-кода. Настройки в pyproject.toml; командное форматирование по умолчанию88символов, если нет иного обоснованного проектного соглашения.

Точные версии библиотек выбираются совместимо с Python3.13, фиксируются uv.lock и проверяются при настройке приложения. Профиль не утверждает, что какой-либо пакет уже установлен. Runtime/dev-зависимости разделены. Установка и запуск — uv sync --locked и uv run --locked с фактической точкой входа.

## Подключаемые модули

| Условие задачи | Компоненты |
|---|---|
| Нужны сохраняемые данные многопользовательского приложения | PostgreSQL17, SQLAlchemy2, asyncpg для async-сценариев, Alembic для версий схемы |
| Подходит изолированное небольшое локальное хранение | SQLite/aiosqlite только после фиксации этого решения; это не доказательство совместимости с PostgreSQL |
| Серверное развёртывание | Docker/Docker Compose, отдельный сервис БД при её наличии, проверки живости/готовности |
| Нужны длительные или периодические операции | Отдельный worker/процесс, явные жизненный цикл, повторы, блокировки и восстановление; конкретная очередь/планировщик выбирается по нагрузке |
| Работа с Excel | OpenPyXL |
| Доступ к Google Таблицам | Google API/Google Auth с нужными полномочиями |
| Требуется управление браузером/браузерная автоматизация | Playwright с относящимися браузерами/ресурсами |

Не устанавливать модули автоматически, если они не нужны выбранному результату. Redis, Celery, React, TypeScript и иные компоненты не входят в этот профиль по умолчанию. Существенно другой frontend/стек фиксируется отдельным решением, а не добавляется незаметно.

## Архитектура

HTTP route → проверенный DTO → прикладной сервис → порт/репозиторий → БД. Внешний API вызывается отдельным клиентом. Нормализатор преобразует данные без HTTP/SQL. Явная сборка зависимостей; прикладная логика не зависит от HTTP-фреймворка.

Составные межслойные контракты именованные: Pydantic, dataclass или TypedDict по назначению. Аннотация TypedDict не заменяет runtime-валидацию внешнего входа. ORM-модели и сессии остаются на границе хранения. Транзакции, идемпотентность и ошибки определяются по сценарию.

Frontend отвечает за разметку/отображение/взаимодействия. Права, обязательная валидация, секреты и бизнес-расчёты остаются на сервере. Не собирать HTML/CSS/UI-подписи в Python бизнес-слоях.

В async-сценариях сетевой/SQL I/O выполняется нативными async-клиентами через await. Не маскировать синхронный сетевой/SQL клиент пулом потоков вместо доступного async-клиента. Для действительно блокирующей сторонней операции определить безопасную изоляцию; не блокировать event loop.

## Проверки и контекст

Для новых Python-тестов достаточно unittest, если задача не выбрала другой инструмент; для JS при подходящем окружении доступен node:test. Интеграционные проверки используют относящиеся изолированные ресурсы. Для UI проверяются затронутые компоновка/переполнение/читаемость/адаптивность и соседние взаимодействия. Не навязывать весь набор проверок инфраструктуры локальному изменению.

В project-profile.md записать profile_id/profile_version, фактическую Python patch-версию, выбранные модули/версии, команды и реальные статусы настройки/проверки. Секреты и личные пути не сохранять. Настройки берутся из окружения; .env.example содержит только безопасные образцы.

PyCharm не требуется: при наличии python-tools использовать SDK IDE, иначе проверить интерпретатор/uv окружение проекта. Существующие версии/пины сохраняются, пока отдельная задача не разрешила миграцию.
