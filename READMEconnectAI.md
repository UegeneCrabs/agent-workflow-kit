# Подключение Agent Workflow Kit

Инструкция для агента. Получив ссылку на библиотеку и поручение подключить её, выполни настройку в выбранной пользователем папке проекта. Не требуй знания кода, ORM или команд Git. Разрешение на подключение включает получение файлов и относящиеся локальные настройки; внешняя отправка изменений, публикация MR/push/deploy требуют соответствующего поручения.

## 1. Выбери цель и источник

- Установи фактическую папку приложения. Репозиторий agent-workflow-kit — источник правил, не целевое приложение. Если цель неизвестна, уточни её до записи.
- Прочитай существующий AGENTS.md, инструкции, README и конфигурацию цели. Не перезаписывай пользовательские файлы/дополнения.
- Получи эту библиотеку по выбранному опубликованному тегу либо commit. Для первой версии — v0.1.0. Прочитай library.json. Не копируй .git, AGENTS.md самой библиотеки, временные файлы и документацию разработки библиотеки как инструкции приложения.
- Нужен реальный доступ к файлам/командам и загрузке репозитория. Если текущий чат его не предоставляет, объясни конкретное ограничение, а не утверждай, что установка выполнена.

## 2. Определи сценарий

**Новый проект.** Спроси только о назначении, пользователях, действиях, данных и существенных предпочтениях. Если запрос выбрал python-business-web, используй [этот профиль](.agents/skills/role-skill-builder/assets/stack-profiles/python-business-web.md). Объясняй пользователю ожидаемое поведение и последствия. Не заставляй бизнес-пользователя выбирать внутренние технологии, уже заданные профилем. Подключай только нужные модули.

**Существующий проект.** Сначала используй готовые правила и контекст. Проверь фактические зависимости, версии, команды и затронутый код. Не опрашивай коллегу об устройстве всего приложения, не меняй стек/версии и не устанавливай новый backend/БД от одного подключения правил. Неизвестную бизнес-логику не выдумывай. При отсутствии контекста составь минимальный фактический профиль со ссылками на существующую документацию; вопросы только по существенным неизвестным.

Если подходящего готового профиля нет, не навязывай python-business-web: установи реальные требования и явно зафиксируй принятое техническое решение.

## 3. Подключи общий набор

- Перенеси .agents/skills/ и .agents/rules/ с их ресурсами в корень цели. Если файлы уже есть, сравни версии и локальные изменения. Совпадающее не дублируй, конфликт не затирай молча; лишние старые файлы автоматически не удаляй.
- Создай или актуализируй project_profile и project_requirements вне .agents/. Стандартные пути: .project-agents/rules/project-profile.md и .project-agents/rules/product-requirements.md. Это контекст проекта, не отдельные новые чаты.
- Используй [шаблон профиля](.agents/skills/role-skill-builder/assets/project-profile-template.md). Запиши идентификатор/версию профиля, фактические Python/зависимости/команды, включённые модули и состояние «выбрано»/«настроено»/«проверено». План не объявляй реализацией.
- По [шаблону AGENTS](.agents/skills/role-skill-builder/assets/project-rules.md) добавь или обнови один маркерный блок, сохрани остальной текст. Объяви project_profile, project_requirements, tasks_dir, validation_dir, research_dir и docs_dir.
- В .project-agents/library-lock.json запиши name, version, repository, фактический commit, выбранный profile_id и перечень установленных путей. Не придумывай неизвестный commit и не включай токены, личные пути или чужую историю.
- В Git проекта должны попадать .agents/, AGENTS.md, общие проектные правила/требования и library-lock.json. Если текущий .gitignore скрывает весь .project-agents, предложи узкое разрешение общих правил и lock, сохраняя исключения tasks/validation/research, личных данных и секретов. Не публикуй ничего автоматически.

## 4. Проверь настройку без лишних прогонов

Проверь наличие файлов, относительные ссылки, один маркерный блок, факты профиля и сохранность прежних инструкций. Чтение README не является установкой.

Определи доступность инструментов делегирования и выбора моделей по возможностям среды. Не запускай испытательные роли/проекты ради самого подключения. Если доступность конкретной модели ещё не подтверждена, честно отметь, что она проверяется при реальном назначении. Недоступную модель нельзя незаметно заменить или выдать за независимую панель.

Для Python используй реально выбранную среду. get_python_environment обязателен в подключённой IDE, когда предоставляется python-tools. В среде без этих инструментов проверь интерпретатор проекта и выбранное uv-окружение без требования установить PyCharm.

Сообщи кратко: куда подключено, версия библиотеки, профиль/обнаруженный стек, что сохранено и какие ограничения остались. Не запускай установку всех зависимостей и всю регрессию от одной редакторской настройки. Подготовка среды нового приложения входит в явно выбранное создание этого приложения.

## 5. Дальше

Пользователь задаёт обычную задачу. Агент читает локальный AGENTS.md и нужные навыки, использует согласованный проектный контекст. READMEconnectAI.md не перечитывается и GitHub не скачивается перед каждой задачей.

Обновление библиотеки — отдельное поручение: сравнить версии/локальные правки, обновить принадлежащие библиотеке файлы и lock, сохранить проектные требования и историю. Не подменять рабочие правила неожиданным latest/main.
