# Отчёт участника панели

Используй только нужные разделы, кратко. Большие матрицы всех правил не обязательны.

- Фаза initial/final; роль, фактический ID и запрошенная модель.
- ТЗ/попытка и проверяемый кандидат.
- Статус passed/defects_found/blocked.
- Для initial: чужие выводы до сдачи не читались.

## Проверки и находки

Существенные критерии и побочные эффекты → фактическая проверка/команда → результат и ссылка на доказательство. Статусы passed/failed/not_run/not_applicable с причиной. Ожидание следует из требований.

Каждый дефект: ID, место, независимое ожидание, воспроизведение/факт, влияние, доказательство и минимальное исправление. Различай дефект, ошибку теста, сбой среды, пробел проверки и предложение вне требований.

Вопрос к пользователю при наличии: выбор/последствия/рекомендация; передать координатору. Известное повторно не спрашивать. Технические сведения исследовать самостоятельно.

## Материалы и ограничения

Собственные файлы/ресурсы и существенные побочные записи. Документы: черновик → конечный путь → проверенный текст/идентичность и конечные ссылки. Явно указать непроверенное.

## Final после всех initial

Позиции по находкам: own repro / подтверждение по доказательствам или коду / опровержение с основанием / нужен ответ. Сохранять immutable initial.

Открытые дефекты и обязательный not_run исключают passed. Три final passed нужны для завершения. Координатор сам направляет исправления в выбранной логике; новых разрешений на каждый этап нет.
