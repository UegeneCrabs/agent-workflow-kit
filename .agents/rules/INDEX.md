# Общие правила разработки

Прочитай этот индекс и профиль по объявленному в корневом AGENTS.md пути `project_profile` перед работой; затем файлы применимых групп. Краткое ТЗ не отменяет применимые правила. ID стабильны. Изменение стандарта/исключения требует явного предмета ТЗ и согласования, не служит способом скрыть дефект.

Роли определяют полномочия, методы — процедуру, эти правила — обязательное качество. [Порядок общения](../skills/task-coordinator/references/user-collaboration.md) отделяет пользовательское описание результата от внутреннего ТЗ: выбранный результат разрешает реализацию, проверки и исправления без отдельного согласия на этапы. Аналитик устанавливает применимость, границы и реальные проверки; кодер выполняет; каждый из трёх тестировщиков независимо проверяет всю совокупность изменений. Координатор фиксирует версию правил и доказательства. Пропущенный аналитиком применимый ID сообщается координатору; выход за область требует новой версии ТЗ.

Для каждой проверки: `passed` — выполнена с доказательством; `failed` — нарушено ожидание; `not_run` — не выполнена с причиной; `not_applicable` — условие не относится к задаче с основанием. Нарушение обязательного правила или `not_run` обязательной проверки блокирует итоговый `passed`. Отсутствующий инструмент/конфиг не означает успех: аналитик включает настройку в согласуемую область либо указывает блокер. Ревью и машинная проверка отмечаются отдельно. Внешнее пожелание не становится скрытым критерием.

Общие BASE и правила честности проверок применяются ко всем задачам. PY — только к Python, ASYNC — к async, DATA-03 — к БД, DATA-04/05 — к соответствующим потокам. Неприменимость технологии не отменяет остальные нормы. Существующие нарушения не дают права исправлять весь проект вне задачи.

## Пути данных подключённого проекта

Корневой AGENTS.md объявляет `project_profile`, `project_requirements`, `tasks_dir`, `validation_dir`, `research_dir` и `docs_dir`. Это пути относительно корня проекта вне переносимого `.agents/`; координатор передаёт их исполнителям в поручении. Не выводи их из расположения SKILL.md и не подставляй имя папки прежнего проекта. Проверь объявленные значения и реальное расположение, включая symlink/junction. Отсутствующее подключение, обязательный профиль или конфликт путей явно сообщи до зависимой работы; не придумывай факты и не создавай данные вне полномочий.

Профиль содержит факты проекта, project_requirements — его требования; tasks_dir — отдельные plan.md/state.md активных задач; validation_dir — изолированные испытания, доказательства и черновики документации; research_dir — локальные исследования; docs_dir — актуальные документы и краткие итоги. Полезное содержание ТЗ и решений сохраняется для MR в постоянном итоге либо доступном внутреннем документе до уборки рабочих файлов. После успешного завершения по протоколу координатора убираются только известные собственные одноразовые материалы; отдельная личная приёмка нужна, если пользователь установил её условием. Постоянные fixtures, чужие задачи и внешние снимки сохраняются; старые задачи автоматически не чистятся. Отсутствующий необязательный исторический разбор не блокирует работу общих правил. Эти данные не входят в переносимый пакет и не подтверждают другой проект.
