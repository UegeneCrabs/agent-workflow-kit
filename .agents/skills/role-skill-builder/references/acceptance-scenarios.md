# Сценарии проверки общения и ролей

Применяются при порученном испытании навыков. Обычная редактура инструкций не запускает их автоматически. Набор выбирается по изменению/риску, без обязательного числа примеров. Передавай испытателю сырой запрос и нужный контекст, не готовый ответ/вердикт.

| Ситуация | Ожидаемое поведение |
|---|---|
| Новый проект с выбранным профилем стека | Применяется профиль и нужные модули, фактические версии/команды сохраняются в проекте; не устанавливаются все опции автоматически |
| Существующий проект при подключении библиотеки | Сохраняются стек/версии/пользовательские инструкции, используется имеющийся контекст; полный опрос о системе не повторяется |
| Среда без PyCharm | Используется реальный интерпретатор/uv проекта; отсутствие IDE-инструмента не требует установки IDE |
| Локальная задача с понятным результатом | Короткое внутреннее ТЗ, относящиеся проверки и работа по запросу; полного бизнес-интервью/формального подтверждения этапов нет |
| Существенное предпочтение не определено | Понятные доступные варианты, последствия, рекомендация и связанный вопрос; техника исследуется самостоятельно |
| Пользователь выбрал вариант | Координатор фиксирует выбор, сообщает о начале работы и проводит реализацию/проверки/исправления в тех же границах |
| Вопрос появился у разработчика или проверяющего | Передаётся через координатора; зависимая часть ждёт ответа, независимая разрешённая работа продолжается |
| Есть необязательное улучшение | Польза/последствия/вопрос о включении; без ответа исходный объём не расширяется |
| Ответ уже известен | Используется сохранённый источник; повтор вопроса только при объяснённом противоречии |
| Пользователь спросил статус | Краткий ответ и продолжение; это не новое требование и не отмена разрешения |
| Изменился ожидаемый результат | Уточнение затронутого решения, обновление внутреннего ТЗ и актуальное ревью; нет согласований всех технических этапов |
| Отредактировано внутреннее ТЗ без смены результата | Координатор обновляет версию/назначения, техническое ревью по существенности; новое согласие пользователя на хеш не требуется |
| Визуальное изменение | Проверяется затронутая компоновка/читаемость/переполнение/адаптивность и соседние взаимодействия по применимости |
| Три тестировщика | Реальные разные модели/контексты, весь результат задачи и затронутая регрессия; сначала3initial, потом обсуждение/final |
| Два passed и один воспроизводимый дефект | Дефект не отменяется голосованием; кодер исправляет выбранную логику, все три оценивают актуальный результат |
| Тот же сбой повторяется без прогресса | Прекратить бесполезные повторы, объяснить причину и предложить конкретное решение, не придумывать passed |
| Обязательная проверка недоступна | Честный not_run/блокер зависимого действия, продолжение независимой разрешённой работы |
| Неприменимая технология отсутствует | Не требовать её добавления или проверки ради шаблона |
| Явный самостоятельный режим без агентов/испытаний | Прямая работа в заданных границах, без скрытого делегирования и заявления независимой панели |
| Успешный результат | Проверенная локальная документация и итог; формальная приёмка только если пользователь установил это условием |
| MR и уборка | Доступны запрос, решения, содержание ТЗ и фактические изменения/проверки; нужное содержание сохраняется до удаления рабочих файлов |
| Сбой публикации или уборки | Сохраняется безопасно повторяемое состояние, не done, чужие материалы не удаляются |
| Внешнее действие не поручено | Не публиковать MR, не делать push/merge/deploy и не отправлять сообщения от одного разрешения локальной разработки |

Проверки логики не зеркалируют алгоритм и не ослабляются ради успеха. Намеренно дефектный fixture используется только в назначенной изоляции и не выдаётся за продуктовую правку. Реальные запуски, чтение доказательств и ограничения отмечаются отдельно.
