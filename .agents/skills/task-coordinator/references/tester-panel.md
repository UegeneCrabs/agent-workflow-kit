# Протокол трёх тестировщиков

Панель входит в выполнение [выбранного пользователем результата](user-collaboration.md), отдельное разрешение на verification и её повторы не требуется. Явное поручение пользователя не запускать агентов имеет приоритет; отсутствие панели в таком режиме указывается честно.

## Кандидат и реальные контексты

Координатор передаёт всем одинаковые запрос/решения, внутреннее ТЗ, изменённые файлы, относящиеся правила/контракты, результат кодера и один кандидат с нужными черновиками документации. Устанавливает отдельные пути записи/временные ресурсы и реальный способ проверки неизменности по [аудиту](change-audit.md).

Три реальных новых контекста: gpt-6-astra, gpt-6.1-sol, gpt-6.1-terra. В collaboration spawn_agent передаёт соответствующее model и fork_turns="none". ID берутся из ответа инструмента. Новый раунд — три новых контекста; обсуждение текущего раунда идёт в тех же. Модель не заменять молча и не имитировать. Недоступность обозначать конкретным blocked, не 2/3 passed.

Каждый проверяет обязательные инструменты в собственном контексте. Среды и порты раздельны по необходимости; существующие подходящие ресурсы не пересоздаются ради каждого запуска. Конкретные ресурсы определяются проектом и риском, универсального требования создавать четыре окружения нет.

## Независимый первый проход

Каждый проверяет всю совокупность изменений текущей задачи и затронутые регрессии. Ожидания следуют из пользовательского результата/контракта. Включаются существенные отказы, побочные эффекты, качество относящихся тестов и документов. Для визуальных изменений применимы компоновка, читаемость, переполнение, адаптивность и соседние взаимодействия. Полный прогон неизменённой инфраструктуры не обязателен.

Не дели файлы между тремя как замену полной оценке задачи. До сдачи всех трёх initial не передавай выводы между участниками и не разрешай читать чужие отчёты. Initial сохраняются неизменными. Отчёт по [шаблону](../../task-tester/assets/review-template.md) может быть коротким: существенные критерии, выполненные проверки, находки, ограничения, доказательства.

Продукт/конфиги неизменны. Собственные probes/артефакты только в назначенных путях, мутации — в своей изолированной копии. Тестировщики не исправляют продукт. Необоснованные skip/xfail и изменение ожидания ради зелёного запрещены.

## Вопросы и обсуждение

Любая роль передаёт координатору вопрос о недостающем пользовательском предпочтении или новом результате. Технический выбор в пределах профиля исследуется самостоятельно. Необязательные улучшения предлагают отдельно, без включения по умолчанию.

После трёх initial дай всем полный набор находок/доказательств. Сохраняй авторов и различай own repro, подтверждение по коду/доказательствам и непройденную проверку. Спор воспроизводится в относящемся объёме; повтор всех успешных проверок без причины не нужен. Два голоса не отменяют воспроизводимый дефект.

Каждый final относится к актуальному кандидату и содержит passed/defects_found/blocked, позиции по находкам и обязательные пробелы. Исправления исходников/документов требуют актуальной проверки всеми тремя; старый verdict автоматически не переносится.

## Исправления и завершение

Координатор без нового пользовательского разрешения возвращает подтверждённые дефекты кодеру в границах выбранной логики. Существенное расширение результата сначала обсуждается с пользователем. При повторе того же дефекта/блокера без прогресса останови бесполезный цикл и объясни причину.

Только три final passed одного актуального результата без открытых дефектов/обязательных not_run допускают завершение. Личная приёмка пользователя — если он установил это условием. Иначе координатор выполняет [финализацию](../SKILL.md#финализация) и сообщает итог без формального вопроса о каждом этапе.
