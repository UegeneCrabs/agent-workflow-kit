# Каталог методов и происхождения

Роль отвечает «что разрешено», метод — «как выполнить», [правила](../../../rules/INDEX.md) — «какое качество обязательно», профиль по объявленному в корневом AGENTS.md пути `project_profile` — «какие технологии и команды существуют». Метод не меняет этап, полномочия и согласования. Координатор/аналитик выбирают только нужные методы и передают их проверенные пути; остальные не загружаются по одному сходству слов.

## Выбор 15 канонических методов

| Метод | Когда выбирать | Ожидаемый результат |
|---|---|---|
| [investigate-codebase](../../investigate-codebase/SKILL.md) | Изучать путь данных, зависимости и существующие проверки перед изменением или для объяснения устройства проекта. | Исследование проекта. |
| [architecture](../../architecture/SKILL.md) | Проектировать контракты и минимальное решение задачи по реальной архитектуре; готовить техническое решение без самостоятельного расширения области. | Проектирование решения. |
| [feature](../../feature/SKILL.md) | Реализовывать согласованное новое поведение в существующей архитектуре, включая FastAPI при его наличии в проекте. | Реализация функции. |
| [bugfix](../../bugfix/SKILL.md) | Воспроизводить согласованный дефект, находить причину и исправлять её с относящейся регрессией в разрешённой области. | Исправление дефекта. |
| [hotfix](../../hotfix/SKILL.md) | Готовить узкое срочное исправление с воспроизведением, проверкой результата и способом восстановления; применять при явно срочной задаче. | Срочное исправление. |
| [small-fix](../../small-fix/SKILL.md) | Выполнять небольшое согласованное изменение без новой архитектуры; оценивать малость по влиянию, а не произвольному числу строк. | Локальная правка. |
| [refactoring](../../refactoring/SKILL.md) | Менять внутреннее устройство кода при сохранении согласованного поведения; использовать исходные проверки и characterization при недостаточном покрытии. | Рефакторинг. |
| [characterization-tests](../../characterization-tests/SKILL.md) | Исследовать и зафиксировать наблюдаемый контракт существующего кода перед изменением, отделяя текущее поведение от известных ошибок. | Фиксация поведения. |
| [tests-unit](../../tests-unit/SKILL.md) | Проверять правила и контракты отдельной единицы кода на контролируемых зависимостях, выводя ожидания из требований. | Модульные тесты. |
| [tests-integration](../../tests-integration/SKILL.md) | Проверять реальные связи компонентов и состояние системы на изолированных ресурсах; выбирать интерфейсы и ожидания из контракта проекта. | Интеграционные тесты. |
| [code-review](../../code-review/SKILL.md) | Рецензировать изменения по контрактам, рискам и обязательным правилам с доказательствами; не вводить отдельную роль или скрытые критерии. | Проверка изменений. |
| [database-migration](../../database-migration/SKILL.md) | Планировать, реализовывать и проверять согласованное изменение схемы БД в изоляции с совместимостью данных и восстановлением. | Миграция данных. |
| [data-engineering](../../data-engineering/SKILL.md) | Проектировать и изменять согласованный ETL, очередь или поток данных с контрактами, полнотой, повторами и восстановлением. | Обработка данных. |
| [docs](../../docs/SKILL.md) | Обновлять относящуюся к задаче документацию по фактическому поведению, контрактам и проверенным командам. | Документация. |
| [mr](../../mr/SKILL.md) | Готовить описание MR/PR по фактическому изменению, проверкам и рискам; публиковать только при соответствующем явном поручении. | Описание изменений. |

Исследование и архитектура обычно помогают аналитику; feature/bugfix/hotfix/small-fix/refactoring — кодеру; unit/integration/characterization/code-review — по текущей роли и её области. Для проверки навыков не требуется DB/ETL; миграции и data-engineering выбираются только при таком предмете. docs и mr не разрешают публикацию или сообщения.

## Соответствие 19 исходным навыкам

Это перечень происхождения относительно исходного .agents/skills, не обязательные внешние пути. Методики адаптированы самодостаточно. Две отличающиеся плоские тестовые версии учтены дополнительно; они не увеличивают число 19 каталоговых SKILL.md.

| № | Исходный каталог | Каноническое место | Что сохранено/изменено |
|---|---|---|---|
| 01 | investigate-codebase | investigate-codebase | Исследование и карта влияния без массового restore. |
| 02 | architecture | architecture | Контракты и решение по фактам; масштаб документации по задаче. |
| 03 | feature | feature | Минимальная функция и проверка контракта. |
| 04 | fastapi-feature | feature | Условная FastAPI-ветка, типы/валидация/слои; не навязывает FastAPI другому стеку. |
| 05 | bugfix | bugfix | Воспроизведение, причина и регрессия. |
| 06 | hotfix | hotfix | Узкая срочная правка и восстановление, согласования сохранены. |
| 07 | small-fix | small-fix | Узкая область по влиянию, без лимита строк/файлов. |
| 08 | refactoring | refactoring | Сохранение поведения и исходные проверки. |
| 09 | safe-refactoring | refactoring | Проверка инвариантов, мутация только в разрешённой копии; устранён конфликт с правом менять тесты. |
| 10 | characterization-tests | characterization-tests | Наблюдаемый контракт отдельно от известного дефекта. |
| 11 | tests-unit | tests-unit | Требования как оракул; дополнительно учтена плоская tests-unit.md, ветви тела лишь ищут пропуски. |
| 12 | tests-integration | tests-integration | Реальные связи и состояние; дополнительно учтена плоская tests-integration.md, без учебного статуса/числа тестов. |
| 13 | code-review | code-review | Проверка типов, слоёв, ошибок, безопасности и полезного результата; не отдельная обязательная роль. |
| 14 | database-migration | database-migration | Ревизии, данные, upgrade и восстановление в изоляции. |
| 15 | data-engineering | data-engineering | Контракты, полнота, повторы/checkpoint и наблюдаемость. |
| 16 | docs | docs | Документация по фактическому коду и проверкам. |
| 17 | mr | mr | Описание изменений и ограничений, без автоматического commit/push. |
| 18 | pipeline | [task-coordinator](../../task-coordinator/SKILL.md) | Состояние и передача; пользователь выбирает результат, координатор ведёт этапы без повторных формальных согласований. |
| 19 | orchestrate-coder-reviewer-summarizer | [task-coordinator](../../task-coordinator/SKILL.md) | Отдельные контексты и доказательства; реальная панель трёх моделей вместо готовых голосов/2 из 3. |

Происхождение норм и ограничения источников описаны в общем INDEX; необязательные локальные исследования ищи по объявленному `research_dir`, если они нужны текущей задаче. Правила обязательны через локальный INDEX, а не через чтение прежних карточек задач или учебного каталога.
