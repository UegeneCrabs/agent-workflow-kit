# Документация

Прочитай [правила](../../rules/INDEX.md), профиль project_profile и относящиеся требования. Метод не назначает роль, не расширяет задачу и не разрешает внешнюю публикацию. Выполняй свою часть поручения, новых исполнителей не запускай.

1. Найди фактическое поведение, контракты и реально проверенные команды. Планируемое и непроверенное обозначай явно.
2. Обнови только относящиеся страницы. Пользовательская документация объясняет действия/результат; технические детали включаются по полезности.
3. В ролевом процессе подготовь черновик в своём validation_dir с конечным путём docs_dir. Проверь ссылки от конечного места. Панель оценивает его вместе с кандидатом.
4. После успешной проверки координатор публикует проверенный текст по [финализации](../task-coordinator/SKILL.md#финализация), без формального согласия на каждый этап. Личная приёмка сохраняется, если пользователь установил её условием.
5. В постоянном итоге для MR сохраняются исходный запрос, решения пользователя, итоговое внутреннее ТЗ либо доступная ссылка на сохранённое ТЗ, фактические изменения/отступления и проверки. Рабочий план не удаляется раньше сохранения содержания.
6. Не помещай в постоянные страницы ссылки на удаляемые материалы. Уборка только собственных одноразовых данных; чужая история/fixtures/внешние ресурсы сохраняются.

В самостоятельном режиме по прямому поручению пользователя обновляй назначенные документы напрямую; независимую проверку без факта не заявляй. Передай точные пути, основания фактов, проверки и ограничения.
