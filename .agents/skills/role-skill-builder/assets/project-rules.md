# Шаблон подключения

Добавь блок ниже в корневой AGENTS.md целевого проекта по запросу подключения. При повторе обнови существующий блок с теми же маркерами, сохрани остальной текст. Ссылки внутри блока рассчитаны на корень целевого проекта после установки полного набора; проверь их там. Профиль заполняется отдельно по фактам. Старые tasks/validation не переносить.

```markdown
<!-- role-workflow:start -->
## Ролевой процесс разработки

Объяви пути относительно корня целевого проекта вне .agents/:
- project_profile: {{relative-profile-file}}
- project_requirements: {{relative-requirements-file}}
- tasks_dir: {{relative-tasks-directory}}/
- validation_dir: {{relative-validation-directory}}/
- research_dir: {{relative-research-directory}}/
- docs_dir: {{relative-docs-directory}}/

Замени placeholders реальными значениями целевого проекта. Проверь существующие профиль/требования; старую историю не копируй. Источник/версию библиотеки и выбранный стек/модули зафиксируй в проектном профиле и library-lock.json; существующий стек не мигрируй от одного подключения правил.

Обычный запрос разработки назначает текущий главный чат координатором: читай [.agents/skills/task-coordinator/SKILL.md](.agents/skills/task-coordinator/SKILL.md). Вопросы и исследование без реализации не запускают конвейер. Явный выбор пользователя работать самостоятельно, без дополнительных агентов или без испытаний имеет приоритет; такой режим не называется независимой панелью.

До работы все роли читают [индекс правил](.agents/rules/INDEX.md), project_profile и project_requirements по объявленным путям, затем относящиеся правила и документацию. Координатор передаёт пути и применимые ID требований в назначения. Общие нормы остаются в .agents/, проектные факты и требования — отдельно; предложения не становятся подтверждённым поведением.

### Общение и договорённость

Следуй [порядку общения](.agents/skills/task-coordinator/references/user-collaboration.md). Пользователь получает понятное описание ожидаемого результата, доступные варианты с последствиями и рекомендацию. Внутреннее ТЗ предназначено разработчику и MR, по умолчанию пользователю не отправляется.

Объём вопросов соответствует задаче. Технические сведения агенты исследуют самостоятельно, известные ответы сохраняют. Любая роль может передать через координатора существенный вопрос о результате/предпочтениях. Дополнительные улучшения предлагаются отдельно и без ответа не включаются. Не задерживай исходную работу ради необязательного предложения.

Выбор варианта либо достаточно определённое поручение разрешает довести выбранный результат до реализации, проверок, исправлений и завершения в этих границах. Координатор фиксирует решение, сообщает «взял в работу» и продолжает. Отдельных согласований этапов, попыток, версии/хеша ТЗ и формальной итоговой приёмки нет, если пользователь сам не установил их условием. Изменение результата, ограничений или внешних полномочий обсуждается до соответствующего действия. Внешняя публикация, MR/push/merge, сообщения другим людям, развёртывание и рабочие данные требуют соответствующего поручения.

### Роли и проверка

Task-analyst author на gpt-6-astra исследует проект и готовит краткое внутреннее ТЗ; отдельный reviewer на gpt-6.1-sol проверяет полноту и выполнимость. Замечания исправляет автор. После passed и разрешённого пользовательским запросом результата координатор назначает task-coder; модель кодера наследуется. Author, reviewer и кодер работают последовательно.

Независимая панель: три отдельных task-tester на gpt-6-astra, gpt-6.1-sol, gpt-6.1-terra по [протоколу](.agents/skills/task-coordinator/references/tester-panel.md). Каждый проверяет весь результат задачи и затронутые регрессии по риску. Сначала независимые initial, затем обсуждение и final всех трёх. Голосование 2/3 не применяется. Исправления в выбранной логике координатор возвращает кодеру без нового пользовательского разрешения, после чего все три проверяют актуальный результат.

Каждый новый этап/попытка получает новый реальный контекст; collaboration fork_turns="none". ID и запрошенные модели фиксируются по ответам инструмента. Уточнение отчёта/обсуждение текущего раунда возможны в прежнем контексте. Недоступных исполнителей не подменять молча и не имитировать. Назначенный исполнитель выполняет поручение и не запускает вложенный конвейер; редактирование инструкций не расширяет его полномочия.

### Область и артефакты

Только координатор ведёт tasks_dir/<осмысленный-slug>/plan.md (внутреннее ТЗ) и state.md (краткий журнал решений, версий, назначений и результатов). ТЗ и проверки соразмерны влиянию задачи; пустые формы и большие одинаковые матрицы не нужны. Чтение зависимостей не разрешает их попутную правку. Пользовательские изменения сохраняются.

Новые задачи используют Markdown plan/state. Старый workflow_gate.py и исторический [workflow-contract](.agents/skills/task-coordinator/references/workflow-contract.md) не являются допуском нового процесса; не создавать фиктивные approvals и не мигрировать прежние задачи автоматически.

Каждый контекст проверяет обязательные инструменты у себя; прежнее наблюдение другого контекста не заменяет проверку. Невыполненное обозначается not_run, не passed. Выполняй только применимые проверки, не повторяй успешные запуски без новых изменений, сбоя или конкретного сомнения.

Кодер готовит нужные черновики в validation_dir, панель проверяет их с кандидатом. После трёх final passed без обязательных пробелов координатор завершает задачу по [финализации](.agents/skills/task-coordinator/SKILL.md#финализация): публикует проверенную локальную документацию, сохраняет в docs_dir/task-results/<slug>.md запрос, решения, содержание итогового ТЗ либо ссылку на сохранённое ТЗ, реализацию и проверки для MR. Рабочие материалы убираются только после сохранения полезного содержания. Известные собственные одноразовые файлы можно убрать; чужие данные/история, постоянные fixtures и внешние ресурсы сохраняются без соответствующего разрешения. Сбой не считается done.

Старые задачи, результаты и исследования не доказывают работу нового проекта и не копируются как его история.
<!-- role-workflow:end -->
```
