# Python и async

Обязательные нормы. Условия и статусы задаёт [INDEX](INDEX.md); факты среды — профиль по пути `project_profile`, объявленному в корневом AGENTS.md. Источники S01–S18 — происхождение правил, а не обязательные внешние зависимости.

## Среда выполнения

Если подключённая IDE предоставляет python-tools/get_python_environment, используй её подтверждённый SDK. В Codex без IDE проверь интерпретатор проекта, requires-python и выбранное uv-окружение. Не требуй установки PyCharm ради отсутствующего IDE-инструмента, не используй случайный Python из PATH. Отсутствие нужного интерпретатора/проверки сообщай конкретно и устраняй только в разрешённой области.

## PY-01

Для Python соблюдать PEP 8 и явно зафиксированные проектные соглашения. Именование, импорты, форматирование и выбранная длина строки должны иметь один источник настроек. Профиль не переопределяет существующие настройки молча.

Применимость: Изменяемый Python-код; lint и format-check обязательны.

Источник и проверка: Требование пользователя + S02. Сверка конфигурации и реальный lint/format-check. В источнике длина 100 — проектное соглашение, не обязательное число PEP 8.

## PY-02

Аннотировать параметры и результаты изменяемых функций, включая None; публичные контракты должны быть конкретными. Не маскировать неизвестные типы через Any, cast, type: ignore или отключение диагностики. Обоснованное локальное исключение требует объяснения.

Применимость: Изменяемые Python-функции и контракты; type-check обязателен.

Источник и проверка: S02–S03, S16. Проверка типов и ревью каждого подавления.

## PY-03

Использовать синтаксис типов и аннотаций, поддерживаемый реальной версией Python проекта. `from __future__ import annotations` применять осознанно; не объявлять его обязательной первой строкой любого файла.

Применимость: Python-аннотации и выбор синтаксиса.

Источник и проверка: Адаптация S03 под SDK проекта. Проверка совместимости, без копирования Python 3.14 из источника.

## PY-04

Не использовать мутируемые аргументы по умолчанию. Значимые константы именовать, настройки брать из принятого механизма конфигурации. Простые очевидные литералы не превращать механически в глобальные константы.

Применимость: Python-параметры, конфигурация и значимые литералы.

Источник и проверка: S03–S04. Линтер и ревью смысла настройки/константы.

## PY-05

Ошибки обрабатываются явно: не применять `except Exception: pass`, не подменять отказ пустым успешным результатом. Сохранять причину исключения и договорённый контракт ошибки; ресурсы освобождать.

Применимость: Затрагиваемая обработка ошибок Python.

Источник и проверка: S03, S07, S09–S10. Негативные сценарии и проверка последствий отказа.

## ASYNC-01

В async-участках не блокировать цикл событий синхронным I/O, не терять await и корректно работать с async-генераторами. Ограничения параллелизма, таймауты, отмена и повторы задаются по задаче.

Применимость: Затронутый async-код; не требует перевода sync-проекта.

Источник и проверка: S03–S04. Проверки типов, async-правил и нужных сценариев отмены/ошибок. Не заставлять синхронный проект становиться async.
